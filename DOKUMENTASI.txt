================================================================================
  II. STRUKTUR AUTENTIKASI & HAK AKSES
================================================================================

  Role yang tersedia:
  -------------------
  1. superAdmin  -- Akses penuh ke semua halaman termasuk Manajemen Akun.
                    Satu-satunya role yang bisa mengelola akun pengguna.
  2. admin       -- Akses ke semua halaman kecuali Manajemen Akun.
                    Bisa tambah, edit, hapus, dan reset data website.
  3. user        -- Hanya bisa melihat data (read-only).
                    Tidak bisa melakukan aksi tambah, edit, hapus, clear.

  Mekanisme Login:
  ----------------
  - User mengisi username (field "name") dan password di halaman /login.
  - PENTING: Login menggunakan field "name" (bukan email) sebagai identifier.
    Ini dikonfigurasi via getAuthIdentifierName() di User model.
  - Laravel session-based authentication (bawaan, tanpa package tambahan).
  - Route login dilindungi throttle (rate limiting) untuk mencegah brute force.
  - Route yang memerlukan login dilindungi middleware "auth".
  - Route /akun dilindungi middleware "role:superAdmin".
  - Route CRUD website dilindungi middleware "role:superAdmin,admin".
  - Setelah login berhasil, user diarahkan ke /dashboard.
  - Logout dilakukan via POST ke /logout (dilindungi CSRF).

  Redirect:
  ---------
  - Mengakses "/" --> otomatis redirect ke /dashboard.
  - Jika belum login --> redirect ke /login.

  Helper Methods di User Model:
  -----------------------------
  - isSuperAdmin() : bool   -- cek apakah role = 'superAdmin'
  - isAdmin()      : bool   -- cek apakah role = 'admin'
  - isUser()       : bool   -- cek apakah role = 'user'
  - canModify()    : bool   -- true jika role adalah superAdmin atau admin
  - getLabel()     : string -- mengembalikan display_name jika ada, fallback ke name

  III. HALAMAN DAN CONTENT

------------------------------------------------------------------------
  1. DASHBOARD  (/dashboard)
------------------------------------------------------------------------

  Deskripsi:
    Halaman ringkasan utama yang memperlihatkan kondisi keseluruhan
    infrastruktur website klien secara sekilas.

  Konten:
    a) 3 Stat Card (atas)
       - Website Active  : jumlah website dengan status "Active"
       - InActive        : jumlah website dengan status "InActive"
       - Suspend         : jumlah website dengan status "Suspend"

    b) Tabel "Akan Expired (30 Hari)"
       - Menampilkan website yang hosting-nya akan habis dalam 1-30 hari.
       - Kolom: Client, Tgl Expired, Sisa Hari.
       - Diurutkan ascending berdasarkan sisa hari (paling mepet di atas).

    c) Tabel "Sudah Expired (Telat Bayar)"
       - Menampilkan website yang hosting-nya sudah melewati tanggal expired.
       - Kolom: Client, Tgl Expired, Hari Terlewat.
       - Diurutkan dari yang paling baru expired.

    d) Bar Chart -- Progres Pendapatan & Margin
       - Menampilkan data revenue dan margin per tahun.
       - Data REAL dari database, dikelompokkan berdasarkan tahun invoice_date.
       - Sumbu Y dinamis: dibulatkan ke atas ke kelipatan Rp 1 juta terdekat.
       - Label tooltip dalam format Rupiah dengan Intl.NumberFormat.

    e) Doughnut Chart -- Status Website
       - Proporsi Active / InActive / Suspend secara visual melingkar.
       - Data real dari database.


------------------------------------------------------------------------
  2. MASTER TABLE  (/master)
------------------------------------------------------------------------

  Deskripsi:
    Data induk seluruh website klien. Menjadi referensi utama yang
    berisi informasi umum setiap website.

  Visualisasi (di atas tabel):
    a) 3 Mini Stat Card -- jumlah website Active, InActive, Suspend
    b) Doughnut Chart -- distribusi status website + persentase tiap status
    c) Total website terdaftar

  Tabel Data:
    Kolom: No, Nama Client, PIC, Nama Website, Jenis Website, Status, PIC Internal, Action.

  Fitur Tabel:
    - Tambah website baru via modal form lengkap
    - Edit data website
    - Hapus website (konfirmasi SweetAlert2)
    - Cari berdasarkan nama client atau website (case-insensitive, LOWER() query)
    - Atur jumlah baris per halaman (10 / 25 / 50)
    - Pagination (AJAX-driven, tanpa full page reload)
    - Sorting per kolom (ascending/descending)
    - Edit Table: konfigurasi dropdown pilihan (jenis website, teknologi, dll)

  Deskripsi:
    Menampilkan informasi domain dari setiap website klien termasuk
    provider, tanggal registrasi/expired, dan biaya tahunan.

  Visualisasi (di atas tabel):
    a) Pricing Tier Cards -- pengelompokan domain berdasarkan harga/tahun:
       - Ekonomis  : Rp 0 - 100.000
       - Standar   : Rp 100.001 - 200.000
       - Premium   : > Rp 200.000

    b) Distribusi Domain Provider -- bar chart proporsi

    Kolom: No, Client, Domain (URL), Provider, Tgl Registrasi, Tgl Expired,

    - Field domain: domain_name, domain_provider, domain_email,
      domain_reg_date, domain_exp_date, domain_duration, is_auto_renew, domain_price
    - Reset section domain via tombol "Clear" (mengosongkan data domain saja)

  4. HOSTING  (/hosting)
------------------------------------------------------------------------

  Deskripsi:
    Mengelola data server/hosting setiap website termasuk tipe hosting,
    provider, kapasitas storage, lokasi server, dan tanggal expired.

  Visualisasi (di atas tabel):
    Expiry Timeline Cards -- satu card per website yang menampilkan:
    - Nama website & client

    - Hijau  : Aman (> 30 hari)

  Tabel Data:

------------------------------------------------------------------------

  Deskripsi:
    Halaman khusus superAdmin untuk mengelola akun pengguna yang dapat

================================================================================
  IV. PERHITUNGAN & LOGIKA BISNIS
================================================================================

  1. SISA HARI HOSTING (days_remaining)
  ----------------------------------------
  Method     : getDaysRemainingAttribute() -- model Website.php
  Rumus      : now()->startOfDay()->diffInDays(hosting_exp_date->startOfDay(), false)
  Keterangan : Menghitung selisih hari antara awal hari ini dengan awal hari
               tanggal expired hosting. Nilai negatif berarti sudah lewat.
               Contoh: jika hari ini 9 Apr 2026 dan exp 20 Mei 2026 --> +41 hari.
               Jika exp 1 Mar 2026 --> -39 hari (sudah expired 39 hari lalu).
               Menggunakan startOfDay() di kedua sisi untuk presisi per-hari.

  2. SISA HARI DOMAIN (domain_days_remaining)
  ----------------------------------------
  Method     : getDomainDaysRemainingAttribute() -- model Website.php
  Rumus      : now()->startOfDay()->diffInDays(domain_exp_date->startOfDay(), false)
  Keterangan : Sama dengan days_remaining namun untuk domain_exp_date.
               Ditampilkan di kolom "Sisa Hari Domain" pada halaman Reminder.

  3. STATUS REMINDER (reminder_status)
  ----------------------------------------
  Method     : getReminderStatusAttribute() -- model Website.php
  Logika     :
    days_remaining < 0   --> "Expired"
    days_remaining < 7   --> "Kritis"
    days_remaining < 30  --> "Segera"
    lainnya              --> "Aman"

  Kategorisasi card di halaman Reminder:
    Darurat = Kritis + Expired (sisa < 7 hari atau sudah expired)
    Siaga   = Segera (7-30 hari)
    Aman    = Aman (> 30 hari)

  4. MARGIN KEUNTUNGAN (margin)
  ----------------------------------------
  Method     : getMarginAttribute() -- model Website.php
  Rumus      :
    margin = sell_price - (domain_price + hosting_price)

  Keterangan : Semua harga dalam satuan yang sama (per periode kontrak).
               Margin negatif berarti perusahaan merugi pada klien tersebut.

  Contoh perhitungan:
    sell_price     = Rp 3.000.000
    domain_price   = Rp 150.000
    hosting_price  = Rp 1.200.000
    margin         = 3.000.000 - (150.000 + 1.200.000) = Rp 1.650.000

  5. STATUS PROFIT (profit_status)
  ----------------------------------------
  Method     : getProfitStatusAttribute() -- model Website.php
  Logika     : margin >= 0 --> "Untung", margin < 0 --> "Rugi"
  Ditampilkan sebagai badge di kolom Status halaman Finansial.

  6. BATAS ATAS GRAFIK MARGIN (dinamis)
  ----------------------------------------
  Lokasi     : finansial.blade.php (JavaScript Chart.js)
  Rumus      : Math.ceil(maxMargin / 1.000.000) * 1.000.000
  Keterangan : Temukan margin tertinggi, lalu bulatkan ke atas ke kelipatan
               Rp 1 juta terdekat.
  Contoh     :
    margin tertinggi = Rp 7.555.000 --> batas atas = Rp 8.000.000
    margin tertinggi = Rp 6.000.000 --> batas atas = Rp 6.000.000 (pas)

  7. STATISTIK PRICING TIER DOMAIN
  ----------------------------------------
  Lokasi     : WebsiteController::buildStatsData() -- section 'domain'
  Logika     :
    tier_low  = domain_price < 100.000
    tier_mid  = domain_price >= 100.000 AND <= 200.000
    tier_high = domain_price > 200.000
    avg_price = rata-rata domain_price seluruh website (non-null)

  8. KELENGKAPAN DATA AKSES
  ----------------------------------------
  Lokasi     : WebsiteController::buildStatsData() -- section 'akses'
  Logika     :
    has_admin_url    = count website di mana admin_url tidak kosong
    has_extra_access = count website di mana extra_access tidak kosong
    has_password_loc = count website di mana password_loc tidak kosong
    Persentase = (count / total) * 100

  9. CEK KELENGKAPAN & KEKOSONGAN DATA
  ----------------------------------------
  Method isIncomplete(section) -- model Website.php
    Mengembalikan true jika ada field wajib section yang belum terisi.
    Dipakai untuk menandai baris yang datanya belum lengkap.

  Method isAllEmpty(section) -- model Website.php
    Mengembalikan true jika SEMUA field section benar-benar kosong.
    Dipakai untuk logika tampilan di tabel (misal: menampilkan indikator
    "belum ada data" vs "data tidak lengkap").

  Section yang didukung kedua method: domain, hosting, akses, finansial, reminder

  --------------------------------

  DELETE /akun/{id}               -- Hapus akun


================================================================================
  VIII. FITUR UMUM DI SEMUA HALAMAN SECTION
================================================================================

  - Search          : Pencarian real-time via AJAX berdasarkan nama client
                      atau website. Case-insensitive menggunakan LOWER() query,
                      kompatibel dengan SQLite maupun MySQL.
  - Pagination      : Navigasi halaman dengan AJAX (tanpa full page reload)
  - Per-page        : Pilih tampil 10 / 25 / 50 baris per halaman
  - Sorting         : Klik header kolom untuk sort ascending/descending
  - Add Data        : Form modal untuk input data baru
  - Edit Data       : Form modal pre-filled dengan data yang dipilih (via AJAX GET)
  - Delete Data     : Konfirmasi hapus via SweetAlert2 (dialog animasi)
  - Clear/Reset     : Reset data satu section (domain/hosting/akses/finansial)
                      tanpa menghapus data section lain pada website yang sama
  - Edit Table      : Kustomisasi opsi dropdown (nilai pilihan di form modal)
  - Dark Mode       : Toggle terang/gelap, tersimpan di localStorage
  - Responsive      : Sidebar collapsible untuk tampilan mobile
  - Sidebar Resize  : Sidebar bisa diubah lebarnya dengan drag (desktop)


================================================================================
  IX. CARA MENJALANKAN APLIKASI (Development)
================================================================================

  1. Install dependensi PHP:
     composer install

  2. Salin file environment:
     copy .env.example .env
     php artisan key:generate

  3. Jalankan migrasi dan seeder:
     php artisan migrate
     php artisan db:seed

  4. Install dependensi Node.js:
     npm install

  5. Build aset frontend (CSS/JS):
     npm run build
     -- atau untuk development dengan hot-reload:
     npm run dev

  6. Jalankan server Laravel:
     php artisan serve

  7. Buka browser: http://localhost:8000

  Catatan: Untuk menjalankan semua proses sekaligus (server + vite + log):
     composer dev


================================================================================
  X. CARA DEPLOY KE PRODUCTION (MySQL)
================================================================================

  Lihat file MYSQL_MIGRATION.md untuk panduan lengkap migrasi SQLite --> MySQL
  dan langkah-langkah deploy ke server production.

  Ringkasan cepat:
  1. Buat database MySQL + user khusus
  2. Update .env (DB_CONNECTION=mysql, APP_ENV=production, APP_DEBUG=false)
  3. php artisan config:clear && php artisan migrate:fresh --seed
  4. composer install --optimize-autoloader --no-dev
  5. npm run build
  6. php artisan config:cache && route:cache && view:cache
